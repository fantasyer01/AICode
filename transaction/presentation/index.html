原子性 - Atomicity

"全部成功或全部失败，不存在中间状态"

  • 操作不可分割
  • 失败时完整回滚
  • 保证数据完整性

✓ 正常流程

开始事务
操作1 成功
操作2 成功
提交事务

✗ 异常流程

开始事务
操作1 成功
操作2 失败
回滚事务

一致性 - Consistency

"数据库从一个一致性状态转换到另一个一致性状态"

  • 满足所有约束条件
  • 业务规则得到执行
  • 数据完整性保持
一致性状态 A
事务执行
中间状态（虚线）
一致性状态 B

隔离性 - Isolation

"并发执行的事务之间互不干扰"

  • 防止数据竞争
  • 控制并发访问
  • 平衡性能与一致性

并发事务执行

事务 1
事务 2
事务 3

✓ 有隔离：事务独立执行
✗ 无隔离：数据混乱冲突

持久性 - Durability

"事务一旦提交，修改永久保存"

  • 数据持久化到磁盘
  • 系统崩溃后可恢复
  • 通过日志机制保证

并发场景下的三大问题

当多个事务同时访问数据库时...

脏读

Dirty Read

Non-Repeatable Read

脏读 - Dirty Read

读取到其他事务未提交的数据

事务 A
更新数据(未提交)
回滚
事务 B
读取数据(脏读)
使用错误数据

生动例子：

小明查询账户余额，事务A正在转账1000元（未提交），小明看到余额增加了1000元。随后事务A回滚，实际余额未变，小明基于错误余额做出消费决策。

不可重复读 - Non-Repeatable Read

同一事务中多次读取同一数据，结果不一致

事务 A
读取数据(值=100)
再次读取(值=200)
事务 B
修改并提交(值=200)

生动例子：

统计报表生成时，第一次查询总金额10000元，其他事务修改了数据，第二次查询总金额12000元，导致报表数据不一致。

幻读 - Phantom Read

同一事务中多次查询，结果集的记录数不一致

事务 A
查询(3条记录)
再次查询(4条记录)
事务 B
插入新记录并提交

生动例子：

查询年龄大于18岁的用户，第一次查询返回100条记录，其他事务新增了符合条件的用户，第二次查询返回105条记录，出现"幻影"记录。
